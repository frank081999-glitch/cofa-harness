# 마무리 — 제출 전 약 25분

1. **동작**: 처음 상태에서 실행 방법대로 다시 돌린다. 테스트 전체를 돌린다.
2. **제출 문서**: `SUBMISSION.md`(또는 과제가 정한 파일명)를 채운다. 재료는 `PLAN.md`·`NOTES.md`·`git log`.
3. **문서와 코드 대조**: 제출 문서의 문장마다 근거(`파일:줄`·커밋·명령 출력)가 실제로 있는지 하나씩 확인한다.
   근거가 없거나 코드와 다른 문장은 고치거나 지운다. 하지 않은 것을 했다고 쓰지 않는다.
4. **약점 세 개**: 사람이 직접 적는다. 형식은 「약점 지점 · 파급 · 다음 검증」.
5. **민감 정보**: `git grep -nE` 로 키·토큰·개인정보 값이 커밋에 없는지 본다.
6. **정리**: `git status` 가 깨끗한지, 과제가 요구한 파일이 정한 경로에 있는지 본다. 마지막 커밋.

## 서술형 대비 (사람)
- 핵심 파일 2~3개를 직접 읽고 「왜 이 구조인가」를 한 문장으로 말해 본다.
- 「장애가 나면」 질문에는 약점 지점 → 파급 → 다음 검증 세 단계로 답한다.
- 질문의 전제가 실제 구현과 다르면 그 차이를 먼저 밝힌다.
