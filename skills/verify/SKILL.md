# 검증 — 기능 하나를 끝낼 때마다

1. **성공 기준 검사**: `PLAN.md` 의 S 번호마다 검사가 하나씩 있다. 없으면 먼저 만든다(작은 `test_*.py` 또는 assert 스크립트 하나).
2. **실행**: 검사를 실제로 돌리고 출력을 보여 준다. 서버가 있으면 사람이 띄운 서버에 부를 `curl` 명령을 적어 사람에게 넘긴다(샌드박스 안 접속은 막힌다).
   검사가 0건 돌았거나 입력이 0행이면 「통과」가 아니라 「미검증」이다. 결과는 통과 · 실패 · 미검증 셋 중 하나로만 말한다.
3. **다른 경로로 대조**: 핵심 숫자 하나를 구현과 다른 방법으로 다시 계산한다.
   - 손으로 셀 수 있는 작은 부분(5~20행)을 골라 기대값을 먼저 적고 비교한다.
   - 또는 다른 도구(`awk`·`sort | uniq -c`·pandas 한 줄)로 같은 값을 낸다.
4. **조용한 실패 확인**: 입력 행 수 = 출력 행 수 + 버린 행 수 인지 센다. 버린 행은 이유별로 센다.
5. **경계 입력**: 빈 입력·중복·예외 규칙에 해당하는 행이 기대대로 처리되는지 한 번씩 본다.
6. **커밋**: 검사가 통과하면 커밋한다. 메시지는 「무엇 — 왜 · 확인: 명령/숫자」.
7. `NOTES.md` 에 한 줄 남긴다.

## 교차 리뷰 (중요 산출물에만: 합의문, 제출 직전 코드)
Codex 의 `/review` 를 쓰거나, 새 Codex 세션(다른 터미널 탭)에서 이렇게 묻는다.

> `PLAN.md` 의 성공 기준과 `git diff <기준커밋>` 을 읽어라. 기준마다 충족·부분·미충족을 판정하고 근거 줄을 대라.
> 이 코드가 틀린 답을 내는 입력을 3개 들어라. 요구에 없는데 만든 것을 들어라. 고치지는 마라.

리뷰 결과 중 채택한 것과 기각한 것을 `NOTES.md` 에 남긴다.
